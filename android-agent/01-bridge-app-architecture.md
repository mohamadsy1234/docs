# هندسة وكيل الذكاء الاصطناعي المستقل على أندرويد: الطبقة الأولى وتطويرات الإنتاج

بعد التشريح العميق والاتفاق على الهيكلية الهجينة ثلاثية الطبقات، ننتقل إلى حسم المكونات المعمارية الحرجة لتطبيق الجسر (Bridge App) بجودة تشغيلية تضمن الصمود 24/7 دون صراعات مع المستخدم أو انهيارات هيكلية.

---

## 1. الوحدات المعمارية المتكاملة لـ Bridge App (Modular Headless Container)

لتفادي الـ Monolith الهش، يُبنى تطبيق الجسر كحزمة من الوحدات المستقلة التي تتواصل عبر موجه داخلي (Local Event Bus):

```
                   ┌──────────────────────────────────────────┐
                   │           Bridge App Container           │
                   │                                          │
                   │  ┌───────────────┐   ┌────────────────┐  │
                   │  │ Notification  │   │ Intent Bridge  │  │
                   │  │   Listener    │   │ (Deep Links)   │  │
                   │  └───────┬───────┘   └───────┬────────┘  │
                   │          │                   │           │
                   │          ▼                   ▼           │
                   │  ┌────────────────────────────────────┐  │
                   │  │      State Coordinator (API)       │  │
                   │  └───────┬───────────────────┬────────┘  │
                   │          │                   │           │
                   │          ▼                   ▼           │
                   │  ┌───────────────┐   ┌────────────────┐  │
                   │  │ Accessibility │   │  Safety Gate   │  │
                   │  │    Engine     │   │ (Isolated Proc)│  │
                   │  └───────────────┘   └────────────────┘  │
                   └───────────────────┬──────────────────────┘
                                       │
                                       ▼ Local WebSocket/HTTP
                           ┌───────────────────────┐
                           │  Python Termux Brain  │
                           └───────────────────────┘
```

### الوحدات الأساسية ووظائفها

1. **Notification Module:** التقاط الإشعارات واستخراج `RemoteInput` للرد الفوري دون فتح التطبيق المستهدف.
2. **Intent Module:** تنفيذ روابط العمق (`whatsapp://`, `tel://`) لتنفيذ 70% من المهام بسرعة فائقة وموثوقية عالية.
3. **Accessibility Module:** الملاذ الأخير (10% من المهام) لقراءة الشاشة المعقدة أو النقر الانتقائي عند غياب الـ Intents.
4. **State Coordinator:** يملك "الحالة الحقيقية" للجهاز وإصدارات الـ Snapshots لمنع عمل الوحدات على حالات قديمة.
5. **Safety Gate Module (عملية منفصلة `android:process=":safety"`):** حارس الأمان المحلي الذي يضم مفتاح الإيقاف (Kill Switch)، محدد المعدل (Rate Limiter)، وفحص HMAC المستقل لضمان منع أي أوامر غير مصرح بها.
6. **Watchdog Supervisor:** يراقب دورياً عمل الوحدات ويعيد ربط الخدمات عند حدوث أي انهيار صامت.

## 2. نموذج التزامن الطبقي (Tiered Concurrency Model)

لمنع تضارب الأوامر بين تدخل المستخدم الفعلي وإجراءات الوكيل في الخلفية، نعتمد نموذجاً ثلاثي الحالات يعتمد على رصد الوجود البشري (`Human Presence Detector`):

```
                    ┌────────────────────────────────┐
                    │     Human Presence Detector    │
                    │  (Screen on? Motion? Touches?) │
                    └───────────────┬────────────────┘
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
       ┌─────────────┐       ┌─────────────┐       ┌─────────────┐
       │  FREE MODE  │       │  SOFT MODE  │       │   LOCKED    │
       │  (لا أحد)   │       │  (المستخدم  │       │  (المستخدم  │
       │             │       │   يتفرج)    │       │   يتفاعل)   │
       ├─────────────┤       ├─────────────┤       ├─────────────┤
       │ Intent ✅   │       │ Intent ✅   │       │ كل شيء ⛔   │
       │ Notif  ✅   │       │ Notif  ✅   │       │ ما عدا      │
       │ A11y   ✅   │       │ A11y   ⚠️   │       │ إشعارات     │
       │             │       │ (تأخير)     │       │ passive     │
       └─────────────┘       └─────────────┘       └─────────────┘
```

- **Free Mode:** الشاشة مغلقة أو لا توجد تفاعلات بشرية؛ جميع قنوات الوكيل تعمل بكامل صلاحياتها.
- **Soft Mode:** الشاشة نشطة لكن المستخدم لا ينقر بفعالية؛ يتم تأخير عمليات Accessibility حرصاً على عدم التشويش، بينما تظل الـ Intents والإشعارات تعمل.
- **Locked Mode:** المستخدم يتفاعل بلمس الشاشة مباشرة؛ يتم تجميد جميع إجراءات التحكم الفوري ويتحول الوكيل إلى وضع الاستماع والمراقبة السلبية (Passive Observation) لتفادي تخريب تجربة المستخدم.

## 3. واجهة برمجة تطبيقات منسق الحالة (State Coordinator API)

لتنظيم تدفق البيانات وضمان دقة المزامنة بين تطبيق الجسر (Kotlin) وعقل الوكيل (Python)، نعتمد عقداً صارماً للبيانات عبر الـ WebSocket:

### أ. طلب الحصول على الحالة (Observe Request)

```json
{
  "action": "observe",
  "target": "whatsapp",
  "depth": "focused",
  "expected_version": 1042
}
```

### ب. رد الحالة (State Snapshot Response)

```json
{
  "screen_id": "whatsapp_chat_view",
  "state_version": 1043,
  "timestamp": 1775012345,
  "elements": [
    {
      "node_id": "node_abc123",
      "text": "مرحباً بك",
      "clickable": true,
      "bounds": [100, 200, 300, 250]
    }
  ]
}
```

### ج. طلب التنفيذ المقترن بالتحقق (Execution Request with ACK)

```json
{
  "action": "execute",
  "target_node_id": "node_abc123",
  "command": "click",
  "min_version_required": 1043
}
```

- **قاعدة Fail-fast:** إذا تغيرت إصدارات الحالة (`state_version`) قبل التنفيذ، يرفض الـ Bridge الطلب تلقائياً لكي لا ينقر الوكيل على زر تغيّر مكانه أو اختفى.

## 4. نموذج التطوير: المسار المزدوج المتوازي (Dual-Track Spiral Roadmap)

بدلاً من التطوير الخطي الذي يؤدي لاكتشاف الثغرات في المراحل الأخيرة، نعتمد مسارين متوازيين:

- **Track A (Bridge App - Kotlin):** بناء الهيكل، ثم Ktor Server، ثم Notification Listener، ثم Accessibility Engine، ثم Safety Gate.
- **Track B (Python Agent - Termux):** بناء العميل الوهمي، ثم ربط HMAC، ثم Event Consumer، ثم State Planner، ثم Meta-Loop.

### بوابات النجاح المرحلية (Milestone Gates)

1. **Sprint 1:** نجاح الاتصال وتأكيد الهوية عبر `curl -H "X-HMAC:..." localhost:8080/ping`.
2. **Sprint 2:** وصول إشعار واتساب إلى بايثون في أقل من 500 ms.
3. **Sprint 3:** قراءة شاشة واتساب وتحويلها إلى بنية JSON صحيحة عبر `Accessibility Engine`.
4. **Sprint 4:** اعتراض الأوامر الخطرة ورفضها تلقائياً إذا انعدم التوقيع الصحيح من Safety Gate.
5. **Sprint 5:** تفعيل نظام التزامن الطبقي وتوقف الوكيل فوراً عند تفاعل المستخدم.
