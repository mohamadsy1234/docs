# تطبيق الجسر (Bridge App) — MVP-1

تطبيق أندرويد (Kotlin) يلتقط إشعارات واتساب، ويرسلها إلى الوكيل في Termux، ويعرض اقتراحه في "إشعار ظل"، ولا يُرسل أي رد إلا بنقرة المستخدم بعد فتح قفل الجهاز. المرجع: [mvp-1-spec.md](../mvp-1-spec.md).

## البنية

| الوحدة | المحتوى | الاختبار |
| --- | --- | --- |
| [`core/`](core) | Kotlin/JVM خالص: البروتوكول، عميل WebSocket، جدول الـ tokens، وكل قرارات Bridge | 24 اختبار JUnit، منها تشغيل متبادل مع وكيل Python الحقيقي |
| [`app/`](app) | طبقة أندرويد رقيقة: `NotificationListenerService`، إشعار الظل، Keystore، شاشة الاقتران والموافقة | فُحصت أنواعها مقابل إطار أندرويد 35، ما عدا ملف واحد (أدناه). **لم تُبنَ ولم تُشغَّل بعد** |

كل منطق القرار في `core`، فطبقة أندرويد لا تقرر شيئاً: تنقل الأحداث وتنفّذ الواجهات.

## البناء

**`core` وحدها** (لا تحتاج Android SDK):

```bash
./gradlew :core:test
```

اختبارات التشغيل المتبادل تحتاج `python3` مع `websockets`، وإلا تُتخطى.

**التطبيق كاملاً** (Android Studio أو سطر الأوامر مع Android SDK):

```bash
./gradlew -Pandroid=true :app:assembleDebug
```

في Android Studio: افتح مجلد `bridge`، وأضف `android=true` إلى `gradle.properties` حتى تظهر وحدة `app`.

## التشغيل على الهاتف

1. ثبّت التطبيق وافتحه. يولّد السر ويعرضه.
2. انقر "نسخ"، ثم في Termux: الصق السطر في `~/.config/agent/.env` ونفّذ `chmod 600 ~/.config/agent/.env`.
3. فعّل مفتاح الموافقة على إرسال النص إلى الوكيل والسحابة. بدونه لا يُرسل Bridge شيئاً.
4. "منح صلاحية قراءة الإشعارات" ثم فعّل Agent Bridge في الإعدادات.
5. "السماح بعرض الإشعارات" (أندرويد 13+).
6. شغّل الوكيل في Termux: `python3 agent.py`. يتصل Bridge به تلقائياً خلال ثوانٍ ويعيد المحاولة إن تأخر.

## ما تحقق منه وما لم يتحقق

**مُختبَر هنا:**

- **تطابق البروتوكول:** الحسابات تطابق `agent/protocol.py` بايتاً ببايت، باختبار قيم ثابتة مولّدة من Python.
- **جولة ظل كاملة مع الوكيل الحقيقي:** إشعار ← اقتراح ← إرسال ← `notification_sent` في Journal الوكيل.
- **الخادم المنتحل:** لا يصله إلا `hello`، لا السر ولا أي محتوى. وتحذير المستخدم بعد ثلاث محاولات فاشلة.
- **قرارات Bridge:** التصفية، وإزالة التكرار، والإبطال عند وصول إشعار أحدث، والاستخدام لمرة واحدة. واسم المرسل والنص المرسل يأتيان من سجل Bridge لا من الوكيل، ولا يمكن استبدال اقتراح بعد عرضه، وتنتهي الصلاحية عند قراءة المحادثة.

**لم يُختبر، ويحتاج الهاتف:**

- **بناء التطبيق وتشغيله أصلاً:** هذه البيئة لا تصل إلى Google Maven، فلا Android SDK ولا Android Gradle Plugin.
- **`WhatsAppNotifications.kt`:** الملف الوحيد الذي لم يُفحص حتى بالأنواع، لأنه يحتاج androidx. هو أيضاً أكثر ملف يعتمد على سلوك واتساب الفعلي: شكل `MessagingStyle`، وطريقة ظهور رسالة المستخدم نفسه، ومكان زر الرد.
- **`setAuthenticationRequired`:** هل يطلب فعلاً فتح القفل قبل الإرسال؟
- **الرد عبر `RemoteInput`:** هل يقبله واتساب؟
- **السماح بـ `ws://` لـ `127.0.0.1`:** هل يعمل عبر `network_security_config`؟

## قائمة تحقق يدوية (Sprint 1، جانب Bridge)

- [ ] رسالة واردة من جهة اتصال → إشعار ظل باسمها والنص المقترح.
- [ ] رسالة في مجموعة، أو رسالة صوتية/صورة → لا إشعار ظل.
- [ ] نقر [إرسال فوراً] والجهاز مقفل → يُطلب فتح القفل أولاً، ثم يصل الرد في واتساب بالنص المعروض حرفياً.
- [ ] فتح المحادثة في واتساب قبل النقر → يختفي إشعار الظل خلال ثانيتين.
- [ ] رسالتان متتاليتان من نفس الشخص → يبقى إشعار ظل واحد، للأحدث.
- [ ] إيقاف الوكيل في Termux ثم تشغيله → يعيد Bridge الاتصال وحده.
- [ ] بعد الإرسال، لا يُقترح رد على رسالتك أنت (الرد لا يُعامل كرسالة واردة).
- [ ] `audit.jsonl` في ملفات التطبيق يسجّل كل إرسال وتجاهل.
