# 01 — مواصفة MVP-1 (وضع الظل والتدريب)

## 1. النطاق والقيود (Scope & Constraints)

* **الحد الأدنى للنظام:** أندرويد 12 (API 31) فما فوق.
* **قناة التفاعل الوحيدة:** `NotificationListenerService` و `RemoteInput`. (لا توجد أي محاولات لقراءة الشاشة عبر Accessibility أو إرسال Intents عميقة).
* **نمط التشغيل:** وضع الظل فقط. الوكيل يقرأ، يحلل، يقترح، وينتظر النقر اليدوي. لا يوجد إرسال تلقائي نهائياً.

---

## 2. آلية الاقتران الآمن (Manual Handshake)

لربط `Bridge App` بسكربت `Python` داخل Termux بشكل آمن:

1. عند فتح Bridge App لأول مرة، يُولّد مفتاح `API_SECRET` (256-bit) ويُخزنه في `EncryptedSharedPreferences`.
2. يعرض التطبيق المفتاح للمستخدم في واجهة بسيطة مع زر "نسخ".
3. يقوم المستخدم بلصق المفتاح في ملف `.env` داخل Termux.
4. كل طلب `HTTP POST` متبادل بين الطرفين يجب أن يحتوي على ترويسة `X-Agent-Auth` تحمل التوقيع.

---

## 3. تدفق البيانات والعمليات (The Event Flow)

### المرحلة 1: التقاط الحدث (Bridge → Python)

1. يصل إشعار واتساب جديد.
2. يتجاهل Bridge App الإشعار إذا كان من "مجموعة" (Group) أو لا يحتوي على كائن `RemoteInput` (مما يعني عدم إمكانية الرد المباشر).
3. يستخرج Bridge App: `(Sender_Name, Message_Text, Notification_ID, Reply_Token)`.
   * *ملاحظة:* `Reply_Token` هو معرف محلي مؤقت يخلقه Bridge App ليُشير إلى كائن `PendingIntent` الخاص بالرد والمحفوظ في ذاكرته، لكي لا يتم تسريب الكائن لبيئة بايثون.
4. يُرسل Bridge App حمولة (JSON) عبر `POST http://127.0.0.1:8000/incoming` إلى Termux.

### المرحلة 2: المعالجة والتوليد (Python Brain)

1. يستلم خادم `FastAPI` في Termux الطلب ويتحقق من التوقيع.
2. يضيف الرسالة إلى سجل السياق الخاص بالمرسل (Context Window).
3. يدمج البصمة الشخصية (System Prompt المستخرج مسبقاً) مع السياق الحالي.
4. يستدعي نموذج LLM (عبر API خارجي مثل Gemini/OpenAI في هذه المرحلة) طالباً رداً قصيراً يناسب السياق.
5. يُرجع بايثون استجابة `HTTP 200 OK` للـ Bridge App تحتوي على:

   ```json
   {
     "action": "propose_reply",
     "reply_token": "token_12345",
     "proposed_text": "تمام، سأكون هناك في الموعد."
   }
   ```

### المرحلة 3: عرض وضع الظل (Bridge Local UI)

1. يستقبل Bridge App اقتراح بايثون.
2. يُصدر Bridge App إشعار أندرويد "محلي" خاص به (System Notification).
3. **محتوى الإشعار:**
   * **العنوان:** 🤖 اقتراح رد لـ [اسم المرسل]
   * **النص:** "تمام، سأكون هناك في الموعد."
   * **زر [إرسال فوراً]:** يحمل خاصية `setAuthenticationRequired(true)`.
   * **زر [تجاهل]:** لإلغاء العملية.

### المرحلة 4: قرار المستخدم (User Action)

* **إذا نقر [تجاهل]:** يتم مسح الـ `Reply_Token` من الذاكرة، ويُرسل طلب لبايثون لتسجيل الحدث كـ "رد مرفوض" للتعلم المستقبلي.
* **إذا نقر [إرسال فوراً]:**
  1. يطلب نظام أندرويد بصمة الإصبع/الرمز السري (إذا كانت الشاشة مقفلة).
  2. بمجرد التحقق، يمرر Bridge App النص المقترح إلى `RemoteInput` الخاص بإشعار واتساب الأصلي.
  3. يتم إرسال الرسالة فعلياً.
  4. يُسجل الحدث في الـ Audit Log.

---

## 4. خطة التطوير لـ Sprint 1 (الأساس)

* **Bridge App:** إنشاء خدمة `NotificationListener`، وتوليد `API_SECRET`، وبناء عميل HTTP بسيط.
* **Python Agent:** إعداد `FastAPI` بمسار واحد يستقبل الـ JSON، يتحقق من التوقيع، ويرد بنص ثابت (Dummy Text) كاختبار قبل ربط الـ LLM الفعلي.
