# مواصفة MVP-1 (وضع الظل والتدريب)

> **الحالة:** المرجع النهائي لـ Sprint 1. حيث تتعارض هذه المواصفة مع [الطبقة الثانية](02-python-agent-brain.md) داخل نطاق الـ MVP، تتقدم المواصفة. تسلسل المفاتيح A/B/C (0.6)، و`plan_token` (0.5.2)، وApp Profiles (0.5.4)، والطبقتان T0/T1 كلها مؤجلة لما بعد الـ MVP.

## 1. النطاق والقيود (Scope & Constraints)

* **الحد الأدنى للنظام:** أندرويد 12 (API 31) فما فوق.
* **قناة التفاعل الوحيدة:** `NotificationListenerService` و`RemoteInput`. لا قراءة للشاشة عبر Accessibility، ولا Intents عميقة.
* **نمط التشغيل:** وضع الظل فقط. الوكيل يقرأ، يحلل، يقترح، وينتظر النقر اليدوي. لا يوجد إرسال تلقائي نهائياً.
* **ما يُتجاهل:** المحادثات الجماعية (`MessagingStyle.isGroupConversation()`)، والإشعارات بلا `RemoteInput`، والرسائل بلا نص (الوسائط).
* **المفاتيح:** سر واحد مشترك (`API_SECRET`) يحل محل تسلسل A/B/C في الـ MVP، بلا دوران. هذا قرار مؤقت واعٍ.

## 2. الاتصال (WebSocket)

* **Python في Termux هو الخادم:** مكتبة `websockets` مع `asyncio`، على `127.0.0.1:8000` حصراً (لا `0.0.0.0` أبداً). لا FastAPI.
* **Bridge App هو العميل:** يتصل بالخادم، ويعيد الاتصال عند الانقطاع بتراجع تصاعدي (1s → 60s).
* **غير متزامن:** Bridge يرسل الحدث ولا ينتظر رداً. حين ينتهي Python من استدعاء LLM (ولو بعد 20 ثانية)، يرسل الاقتراح عبر نفس القناة.

### 2.1 الاقتران (Pairing)

1. عند فتح Bridge App لأول مرة، يُولّد `API_SECRET` (256-bit) ويحفظه مشفّراً بمفتاح AES في Android Keystore. (`EncryptedSharedPreferences` مُعلَّمة deprecated في `androidx.security-crypto`، فلا يُعتمد عليها.)
2. يعرض التطبيق المفتاح مع زر "نسخ". النسخ إلى الحافظة يحمل العلَم `ClipDescription.EXTRA_IS_SENSITIVE` إلزامياً (أندرويد 13+)، فلا يظهر في معاينة الحافظة.
3. يلصق المستخدم المفتاح في `~/.config/agent/.env` داخل Termux، بصلاحيات `600`.
4. **السر لا يُرسل عبر الاتصال أبداً،** لا في المصافحة ولا بعدها.

### 2.2 المصافحة المتبادلة (Mutual Handshake)

**لماذا متبادلة:** أندرويد لا يعزل منافذ `127.0.0.1` بين التطبيقات. إن حجز تطبيق آخر المنفذ 8000 قبل Termux، فسيتصل Bridge به. لو كانت المصافحة "أرسل السر"، لسُلّم السر للمنتحل. ولو كان Bridge وحده يُثبت هويته، لاستقبل المنتحل محتوى الإشعارات. لذلك **يُثبت الخادم هويته أولاً، ولا يرسل Bridge أي بيانات قبل ذلك.**

```text
Bridge (client)                                   Python (server)
  │── hello {nonce_b} ───────────────────────────────►│
  │◄── {nonce_s, proof_s = HMAC(secret, "server"‖nonce_b‖nonce_s)} ──│
  │   يتحقق Bridge من proof_s؛ عند الفشل: إغلاق فوري    │
  │── {proof_b = HMAC(secret, "client"‖nonce_s‖nonce_b)} ──────►│
  │                                   يتحقق Python من proof_b؛ عند الفشل: إغلاق
  │══ الجلسة مفتوحة: K_s = HMAC(secret, "session"‖nonce_b‖nonce_s) ══│
```

* `nonce_b` و`nonce_s` عشوائيان بطول 128-bit لكل اتصال.
* كل رسالة بعد المصافحة تحمل `seq` متزايداً و`mac = HMAC(K_s, seq‖payload)`. أي رسالة بـ `mac` خاطئ أو `seq` مكرر أو غير متتالٍ = إغلاق الاتصال.
* فشل المصافحة يُسجَّل في الطرفين. إن فشل `proof_s` ثلاث مرات متتالية، يُصدر Bridge إشعاراً للمستخدم: "خادم غير موثوق على المنفذ 8000".
* كل إعادة اتصال = مصافحة جديدة ومفتاح جلسة جديد.

### 2.3 أنواع الرسائل

| الاتجاه | `type` | الحقول | المعنى |
| --- | --- | --- | --- |
| Bridge → Python | `incoming` | `event_id`، `reply_token`، `sender_name`، `text`، `posted_at` | رسالة واردة قابلة للرد |
| Python → Bridge | `propose_reply` | `reply_token`، `proposed_text` | اقتراح رد |
| Bridge → Python | `notification_sent` | `reply_token`، `sent_text`، `sent_at` | المستخدم وافق والإرسال نجح |
| Bridge → Python | `proposal_ignored` | `reply_token` | المستخدم نقر [تجاهل] |
| Bridge → Python | `notification_expired` | `reply_token` | إشعار واتساب الأصلي أُزيل؛ يتوقف Python عن أي عمل معلّق عليه |

مثال (الغلاف `seq`/`mac` محذوف للاختصار):

```json
{
  "type": "propose_reply",
  "reply_token": "rt_9f2c41d0",
  "proposed_text": "تمام، سأكون هناك في الموعد."
}
```

## 3. تدفق البيانات والعمليات (The Event Flow)

### المرحلة 1: التقاط الحدث (Bridge → Python)

1. يصل إشعار واتساب جديد أو مُحدَّث (`onNotificationPosted`).
2. يتجاهله Bridge إن كان من مجموعة، أو بلا `RemoteInput`، أو آخر رسالة فيه بلا نص.
3. **إزالة التكرار:** واتساب يعيد نشر الإشعار نفسه مع كل تحديث. مفتاح الحدث `event_id` = مفتاح الإشعار (`sbn.key`) + الطابع الزمني لآخر رسالة. الحدث المكرر لا يُرسل.
4. يُنشئ Bridge `Reply_Token` عشوائياً (128-bit) يُشير في ذاكرته المحلية إلى: `PendingIntent` و`RemoteInput` الخاصين بالرد، واسم المرسل، و`sbn.key`، ووقت الإنشاء. الكائنات نفسها لا تغادر Bridge أبداً.
5. إن كان لنفس `sbn.key` token سابق، يُبطَل ويُلغى إشعار الظل المرتبط به، لأن أحدث إشعار هو الصالح.
6. يرسل Bridge رسالة `incoming`. إن لم يكن الاتصال قائماً، يُسقَط الحدث ويُسجَّل (لا طابور في الـ MVP).

### المرحلة 2: المعالجة والتوليد (Python Brain)

1. يستلم الخادم الرسالة ويتحقق من `mac` و`seq`.
2. يتجاهل `event_id` مكرراً.
3. يضيف الرسالة إلى سياق **هذا المرسل وحده** (لا سياق مشترك بين المحادثات، حسب 0.5.7).
4. يدمج البصمة الشخصية (System Prompt المستخرج مسبقاً) مع السياق.
5. يستدعي LLM سحابياً بمهلة 30 ثانية. عند انتهاء المهلة أو الفشل: لا اقتراح، ويُسجَّل السبب.
6. يرسل `propose_reply`.

### المرحلة 3: عرض وضع الظل (Bridge Local UI)

1. يبحث Bridge عن `reply_token` في ذاكرته. **إن لم يجده، يتجاهل الرسالة فوراً ويسجّلها.** Bridge هو مصدر الحقيقة الوحيد.
2. يحفظ `proposed_text` في سجل الـ token. هذا النص بالذات هو ما سيُرسل، لا غيره.
3. يُصدر Bridge إشعاراً محلياً:
   * **العنوان:** 🤖 اقتراح رد لـ [اسم المرسل] — **من سجل Bridge**، لا من أي حقل يرسله Python.
   * **النص:** النص المقترح كاملاً.
   * **زر [إرسال فوراً]:** يحمل `setAuthenticationRequired(true)`.
   * **زر [تجاهل]:** لإلغاء العملية.

### المرحلة 4: قرار المستخدم (User Action)

* **إذا نقر [تجاهل]:** يُحذف الـ token، ويُرسل `proposal_ignored` لتسجيله كرد مرفوض للتعلم.
* **إذا نقر [إرسال فوراً]:**
  1. إن كان الجهاز مقفلاً، يطلب النظام فتح القفل (بصمة أو رمز).
  2. يضع Bridge النص المحفوظ في `RemoteInput` الخاص بإشعار واتساب الأصلي ويُطلق الـ `PendingIntent`.
  3. **عند النجاح:** سطر في Audit Log المحلي، ثم `notification_sent` إلى Python، ثم حذف الـ token.
  4. **عند الفشل** (`PendingIntent.CanceledException` أو أي خطأ): إشعار للمستخدم "تعذّر الإرسال: الرسالة الأصلية لم تعد متاحة"، وسطر في Audit Log.

### دورة حياة الإشعار

* **إزالة إشعار واتساب الأصلي** (`onNotificationRemoved`، مثلاً لأن المستخدم فتح المحادثة): يُلغي Bridge فوراً كل إشعارات الظل المرتبطة بـ `sbn.key`، ويحذف الـ tokens، ويرسل `notification_expired`.
* **token بلا إشعار ظل** (لم يصل اقتراح): يُحذف بعد 24 ساعة.
* **موت عملية Bridge:** الـ tokens في الذاكرة تضيع. أي نقرة لاحقة على إشعار ظل قديم تجد token مفقوداً، فتُظهر "انتهت صلاحية الاقتراح" ولا تُرسل شيئاً.

## 4. Audit Log

* **Bridge هو الكيان الوحيد الذي يعرف الحقيقة،** فالسجل المرجعي عنده: ملف إلحاقي فقط في تخزين التطبيق الخاص.
* كل سطر: الوقت، والحدث (`sent` / `ignored` / `expired` / `send_failed` / `handshake_failed`)، والـ token، واسم المرسل، والنص المرسل عند `sent`.
* Python يحدّث سجله وسياق المحادثة من رسائل `notification_sent` و`proposal_ignored`، لكن سجله ثانوي.

---

## 5. الخصوصية: استثناء السحابة

* MVP-1 يستخدم LLM سحابياً (Gemini أو OpenAI) **كاستثناء اضطراري للمرحلة الحالية**. كل رسالة واردة تُعالَج تخرج من الجهاز إلى مزوّد خارجي.
* **يتطلب موافقة المستخدم الصريحة:** يعرض Bridge شاشة موافقة عند أول تشغيل، ولا يرسل أي `incoming` قبل الموافقة. سحب الموافقة يوقف الإرسال فوراً.
* مفتاح API الخاص بالمزوّد يُحفظ في `~/.config/agent/.env` بصلاحيات `600`.
* استنساخ الأسلوب (00-goal، 3.1) يبقى محلياً بالكامل.

## 6. خطة Sprint 1 (الأساس)

* **Bridge App:** خدمة `NotificationListener` مع الفلترة وإزالة التكرار، وتوليد `API_SECRET` وشاشة النسخ، وعميل WebSocket بالمصافحة المتبادلة، وجدول الـ tokens، وإشعار الظل بزرّيه، وAudit Log، وشاشة الموافقة.
* **Python Agent:** خادم `websockets` على `127.0.0.1:8000` بالمصافحة المتبادلة، يرد على كل `incoming` بنص ثابت (Dummy Text) قبل ربط LLM الفعلي.

### معايير قبول Sprint 1

* [ ] خادم بسر خاطئ → Bridge يغلق الاتصال بعد `proof_s`، ولا يرسل أي `incoming`.
* [ ] خادم منتحل على المنفذ 8000 يسجّل كل ما يصله → لا يصله السر ولا أي محتوى إشعار.
* [ ] رسالة بـ `mac` خاطئ أو `seq` مكرر → إغلاق الاتصال.
* [ ] `propose_reply` بـ token غير موجود → يُتجاهل ويُسجَّل، ولا يظهر إشعار.
* [ ] 20 رسالة متتالية من جهات مختلفة → 20 إشعار ظل، بلا تكرار.
* [ ] فتح المحادثة في واتساب → إشعار الظل يختفي خلال ثانيتين.
* [ ] نقر [إرسال فوراً] والجهاز مقفل → يُطلب فتح القفل قبل الإرسال.
* [ ] صفر رسائل مرسلة دون نقر المستخدم على [إرسال فوراً] (مُتحقَّق من Audit Log).
